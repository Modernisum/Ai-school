# Responsibility Feature — Gap Analysis & Improvement Plan

## Executive Summary

The Responsibility feature is Vidhyam's core differentiator — it interconnects HR (Employees), Finance (Salary/Fees), and Infrastructure (Spaces). The current implementation is extensive (~35 backend routes, 10+ React components, 6+ Flutter screens) but has **5 critical bugs**, **8 high-severity gaps**, and **10 medium issues** across all 4 application layers.

---

## 1. Backend (Rust/PostgreSQL)

### 1.1 🔴 CRITICAL — SQL Injection Vulnerabilities

**Location:** `Backend/src/repository/misc_repo.rs:544-550`
```rust
let total_query = format!(
    "SELECT COUNT(*) FROM responsibilities WHERE school_id = '{}'{}",
    school_id,
    employee_type.as_ref().map(|et| format!(" AND employee_type = '{}'", et)).unwrap_or_default()
);
```
**Problem:** `school_id` and `employee_type` are embedded directly into SQL via `format!()` instead of using bind parameters. An attacker can inject SQL through these parameters.

**Same pattern exists in service layer:** `responsibility_service.rs` lines 630-648, 856-886, 913-926, 960-976.

**Fix:** Replace all string-formatted SQL in responsibility-related queries with parameterized `sqlx::query()` bind parameters.

### 1.2 🔴 CRITICAL — Bulk Assign/Remove Are Placeholders

**Location:** `Backend/src/routes/responsibility.rs:314-443`

**Problem:** `bulk_assign_responsibility` and `bulk_remove_responsibility` only:
1. Publish WebSocket events
2. Send notifications
3. Return success messages

They **never call the repository layer** to actually persist the changes to the database.

**Fix:** Wire up actual DB operations:
- `bulk_assign` → call `repo.assign_employees_with_spaces()` for each employee
- `bulk_remove` → call `repo.remove_responsibility()` for each employee
- Add proper transaction wrapping

### 1.3 🔴 CRITICAL — INSERT Column Mismatch in `add_responsibility`

**Location:** `Backend/src/repository/misc_repo.rs:606`

**Problem:** The INSERT statement's column list doesn't match the bound parameters. The SQL hardcodes `space_id = NULL` and has mismatched column count versus params.

**Fix:** Update the INSERT statement to match the current schema after all migrations:
- Remove `space_id` column (dropped in `202604080000` migration)
- Ensure all required columns present: `school_id`, `responsibility_id`, `name`, `description`, `employee_type`, `monthly_price`, `per_day_price`, `student_fee`, `time_period`, `data`
- Reduce bound params to match actual column count

### 1.4 🟠 HIGH — `search_responsibilities` Returns Empty Array

**Location:** `Backend/src/routes/responsibility.rs:289-310`

**Problem:** The search route is a stub — it always returns `"data": []` regardless of input.

**Fix:** Implement actual full-text/pattern search against the `responsibilities` table using `ILIKE` or PostgreSQL trigram indexes (already created in migration `202604110000`).

### 1.5 🟠 HIGH — No Typed Models — All `serde_json::Value`

**Problem:** Every responsibility request/response uses untyped `Value`. This means:
- No compile-time validation of field names or types
- CamelCase vs snake_case mismatches are silent runtime errors
- Fields like `monthly_price` can be string/int/null causing crashes downstream

**Fix:** Create typed Rust structs:
```rust
pub struct Responsibility {
    pub responsibility_id: String,
    pub school_id: String,
    pub name: String,
    pub description: Option<String>,
    pub employee_type: String,
    pub monthly_price: Option<Decimal>,
    pub per_day_price: Option<Decimal>,
    pub student_fee: Option<Decimal>,
    pub time_period: Option<i32>,
    pub data: Option<Value>,
    pub created_at: DateTime<Utc>,
    pub updated_at: DateTime<Utc>,
}
```
Use `serde::Serialize`/`Deserialize` and `sqlx::FromRow` for all DB interactions.

### 1.6 🟠 HIGH — Type Mismatch: `TEXT[]` vs `JSONB` in History/Version Tables

**Location:** Migration `202604090000_responsibility_history.sql`

**Problem:**
- `responsibility_assignment_history.space_ids` is `TEXT[]`
- `responsibility_version.space_ids` is `TEXT[]`
- Main table `employee_responsibilities.space_ids` is `JSONB`

This causes serialization/deserialization friction and potential data loss when converting between formats.

**Fix:** Change history/version tables to use `JSONB` for `space_ids` (consistent with the main table), or use a new migration to align types.

### 1.7 🟡 MEDIUM — Pagination Ignored in Student Listing

**Location:** `responsibility_service.rs:227-239`

**Problem:** `list_student_responsibilities_paginated` accepts `page` and `limit` params but the internal call doesn't pass them through — returns the full list every time.

**Fix:** Wire pagination through to the repository query.

### 1.8 🟡 MEDIUM — `get_responsibility_analytics` Uses Fragile `room_number` Matching

**Location:** `misc_repo.rs:751-766`, `responsibility_service.rs:818`

**Problem:** Analytics builds space-to-student mapping by joining on `room_number`, assuming space names follow a convention that matches student `room_number`. This is brittle and will break if naming schemes diverge.

**Fix:** Use the explicit `employee_responsibilities.space_ids` JSONB field to find students by looking up which students belong to each space actually assigned.

### 1.9 🟡 MEDIUM — `responsibility_version` FK to `admins` via `created_by`

**Location:** Migration `202604090000:57-60`

**Problem:** `responsibility_version.created_by` references `admins(admin_id)` with `ON DELETE SET NULL`. This means when an admin is removed, version history loses authorship tracking.

**Fix:** Use `ON DELETE SET DEFAULT` to a system account, or keep `SET NULL` but add a fallback display name in queries.

## 2. Frontend (React/RTK Query)

### 2.1 🔴 CRITICAL — Duplicate API Definitions

**Files:**
- `frontend/Vidhyam/src/features/infrastructure/infrastructureApi.js` (root, 458 lines, lines 253-407)
- `frontend/Vidhyam/src/features/infrastructure/api/responsibilityApi.js` (139 lines)

**Problem:** Two files independently call `baseApi.injectEndpoints()` with the same `"Responsibility"` tag. Since `overrideExisting` defaults to `false`, the second file's definitions are **silently ignored** when names overlap. Different components import from different files, so some use the root version and some use the sub-folder version — different endpoints, different signatures, different tag structures.

**Conflicts:**
| Endpoint | Root (`infrastructureApi.js`) | Sub-folder (`api/responsibilityApi.js`) |
|---|---|---|
| `getResponsibilities` | `{schoolId, employeeType, idsOnly}` | `(schoolId)` — no filters |
| `overviewAnalytics` | `{schoolId, timeRange}` | `(schoolId)` — no timeRange |
| `rollback` | POST to `/rollback` with body `{version}` | POST to `/rollback/{version}` |
| `bulkAssign` | `{schoolId, responsibilityId, body}` | Same but URL may differ |
| History/Version paths | `/responsibility/{schoolId}/{id}/history` | `/responsibility/{schoolId}/responsibilities/{id}/history` |

**Fix:**
1. Consolidate ALL responsibility endpoints into ONE API definition file
2. Remove the duplicate `api/responsibilityApi.js`
3. Update all component imports to use the surviving file
4. Ensure consistent URL patterns across all endpoints

### 2.2 🟠 HIGH — WebSocket Uses Wrong Query Client Library

**Location:** `frontend/Vidhyam/src/features/infrastructure/hooks/useResponsibilityWebSocket.js`

**Problem:** The hook imports `useQueryClient` from `@tanstack/react-query` and calls `queryClient.invalidateQueries()` — but the app uses **RTK Query** for data fetching. The invalidation is a **no-op** — RTK Query caches are never invalidated by WebSocket events.

**Fix:** Replace the React Query invalidation with RTK Query's dispatch-based cache invalidation:
```js
import { useDispatch } from 'react-redux';
import { apiSlice } from '../../app/api/baseApi';
// On event: dispatch(apiSlice.util.invalidateTags(['Responsibilities']))
```

### 2.3 🟠 HIGH — Unused `pollingInterval` Prop

**Location:** `frontend/Vidhyam/src/features/infrastructure/pages/ResponsibilityPage.jsx`

**Problem:** The page receives `pollingInterval` from its parent (`infra.jsx`) but never passes it to any RTK Query hook. The prop is accepted in `props` but never read.

**Fix:** Either wire `pollingInterval` into the relevant `useGetResponsibilitiesQuery` hook call, or remove the prop from parent and child if polling is not needed.

### 2.4 🟠 HIGH — Unused Imports in ResponsibilityHub

**Location:** `frontend/Vidhyam/src/features/infrastructure/components/responsibility/ResponsibilityHub.jsx`

**Problem:** 5 hooks are imported but never called — the component uses raw `fetch()` for CSV and PDF downloads instead:
- `useExportCsvQuery`
- `useGetUtilizationReportQuery`
- `useGetWorkloadReportQuery`
- `useGetSpaceDistributionReportQuery`
- `useGetRevenueReportQuery`

**Fix:** Either use the imported RTK Query hooks, or remove the unused imports.

### 2.5 🟡 MEDIUM — No Test Coverage for Core Components

**Files with tests:** Only `SpaceResponsibilityTab.test.jsx` (48 lines) exists.

**Missing tests:** `ResponsibilityPage`, `ResponsibilityHub`, `ResponsibilityList`, `ResponsibilityForm`, `ResponsibilityDetailView`, `BulkAssignModal`, `ResponsibilityAnalytics`.

### 2.6 🟡 MEDIUM — Non-standard Icon Imports at Bottom of Files

**Locations:**
- `ResponsibilityAnalytics.jsx:152` — `Clock` imported at bottom
- `ResponsibilityForm.jsx:122` — `Zap` imported at bottom

### 2.7 🟡 MEDIUM — CSV/PDF Download Uses Raw `fetch()` Instead of RTK Query

**Location:** `ResponsibilityHub.jsx`

**Problem:** CSV export and PDF report downloads use manual `fetch()` with JWT token extraction instead of the RTK Query hooks that were set up for this purpose. This bypasses RTK Query's caching and error handling.

## 3. Mobile Employee (Flutter)

### 3.1 🔴 CRITICAL — TasksBloc Uses Mock Data

**Location:** `Apps/employee/lib/blocs/tasks/tasks_bloc.dart`

**Problem:** The `TasksBloc` returns 3 hardcoded `DutyItem` objects. The `ResponsibilityDetailScreen` calls `ApiService.completeTask()` (real API), but:
1. The initial task list always shows mock data regardless of actual DB state
2. Completed tasks reset to mock data when the BLoC is recreated
3. Real DB completions are never reflected in the UI

**Fix:**
- Remove `TasksBloc` mock data entirely
- Wire `TasksBloc` to call `ApiService.getTasksByResponsibility()` on load
- Use real API responses instead of hardcoded items

### 3.2 🔴 CRITICAL — No Responsibility Model Class

**Problem:** All responsibility data is typed as `dynamic` throughout the app (lists, maps, etc.). This causes:
- Runtime crashes from unexpected `null` values (e.g., `r["monthly_price"]` could be string, int, null)
- No autocomplete, no compile-time safety
- `_totalRevenue` uses `.toDouble()` on `dynamic` — crashes if value is string
- `_totalSpaces` uses `cast<String>()` — crashes if space_ids contains non-strings

**Fix:** Create shared Dart model classes:
```dart
class Responsibility {
  final String id;
  final String name;
  final String? description;
  final String employeeType;
  final double? monthlyPrice;
  final double? perDayPrice;
  final double? studentFee;
  final List<String> spaceIds;
  // ... factory from JSON, to JSON
}
```
Create shared package or copy to both mobile apps.

### 3.3 🟠 HIGH — No `mounted` Checks Before `setState`

**Locations:**
- `responsibility_detail_screen.dart` — `_loadResponsibilityDetail` calls `setState` after `Navigator.push` without `mounted` check
- `space_assignment_view.dart` — `_loadSpaces` and `_saveAssignments` same issue

**Fix:** Add `if (!mounted) return;` before every `setState` call in async callbacks.

### 3.4 🟠 HIGH — API URL Hardcoded

**Location:** `Apps/employee/lib/api_service.dart:17`
```dart
static const String serverUrl = 'http://localhost:8080';
```

**Fix:** Move to environment config or a shared config file, with support for different environments (dev/staging/prod).

### 3.5 🟡 MEDIUM — `updateResponsibilitySpaces` Has Inconsistent URL Pattern

**Location:** `Apps/employee/lib/api_service.dart:398`
```
PUT /api/responsibility/{schoolId}/responsibilities/{id}/bulk-update
```
Note the double `responsibility` in path — `/responsibility/{schoolId}/responsibilities/{id}/...`

### 3.6 🟡 MEDIUM — No Pull-to-Refresh on Responsibility List

**Location:** `responsibility_list_screen.dart`

**Fix:** Wrap `ListView` in `RefreshIndicator` and call `_loadResponsibilities()` on refresh.

## 4. Mobile Chatra (Flutter — Student App)

### 4.1 🟠 HIGH — Call/Email Buttons Are UI Stubs

**Location:** `Apps/chatra/lib/features/responsibility/widgets/teacher_contact_card.dart`

**Problem:** Call and Email icon buttons have empty `onPressed` handlers with comments `// Call functionality` and `// Email functionality`.

**Fix:** Add `url_launcher` package and implement:
```dart
onPressed: () => launchUrl('tel:${teacher['phone']}')
onPressed: () => launchUrl('mailto:${teacher['email']}')
```

### 4.2 🟠 HIGH — Dashboard BLoC Doesn't Include Responsibility Data

**Location:** `Apps/chatra/lib/features/dashboard/bloc/dashboard_bloc.dart`

**Problem:** The student dashboard fetches profile, attendance, timetable, and fees — but **skips responsibility data entirely**. Students can't see their teachers/responsibilities from the home screen.

**Fix:** Add `getStudentResponsibilities()` call in the parallel `Future.wait` block and include teachers/responsibilities in `DashboardLoaded` state.

### 4.3 🟡 MEDIUM — `₹null` Displayed When Amount is Null

**Location:** `Apps/chatra/lib/features/responsibility/screens/fee_breakdown_screen.dart:`

**Fix:** Add null-safe formatting for all monetary displays.

### 4.4 🟡 MEDIUM — Inconsistent API Response Handling

**Problem:** Employee's `ApiService` returns `null` on error. Chatra's `ApiService` returns `ApiError` object. Different patterns for the same class of method.

**Fix:** Standardize response handling — either both use `ApiError` or both return `null`, depending on the preferred pattern.

## 5. Missing Features (Admin UI Enhancements)

Based on the user's description, these features are conceptualized but not yet implemented:

### 5.1 🟠 HIGH — Financial Overview Widget

**Concept:** Space Dashboard showing total salary cost for each space category.

**Implementation needed:**
- **Backend:** Add an API endpoint: `GET /schools/{schoolId}/spaces/{spaceId}/financial-overview` returning total monthly salary cost, total student fees, net profit/loss per space
- **Frontend:** Create `FinancialOverviewWidget` component for Space Dashboard
- **Data:** Aggregate `monthly_price` from all `employee_responsibilities` linked to this space via `space_ids`

### 5.2 🟠 HIGH — Critical Alerts for Missing Responsibilities

**Concept:** If a space is missing a required responsibility (e.g., no class teacher for a classroom), show a red/yellow alert on the dashboard.

**Implementation needed:**
- **Backend:** Add `space_requirements` table query to find gaps:
  `GET /schools/{schoolId}/alerts/missing-responsibilities`
- **Frontend:** Alert banner component on dashboard showing unassigned critical responsibilities

### 5.3 🟡 MEDIUM — Missing Staff Indicators in SpaceResponsibilityTab

**Current state:** `SpaceResponsibilityTab.jsx` shows `UNASSIGNED` text in amber for unassigned responsibilities — this partially exists.

**Enhancement needed:**
- The `r.employeeName` check works, but the component doesn't distinguish between "required but unassigned" vs "optional and unassigned"
- Add `isRequired` field from `space_requirements` table
- Show different badges: `⚠ REQUIRED` (red) vs `○ OPTIONAL` (gray)

### 5.4 🟡 MEDIUM — Smart Conflict Detection (Frontend Validation)

**Concept:** When admin tries to assign an employee who is already assigned to the same responsibility in the same space, show a pop-up alert.

**Current state:** Backend has duplicate check in `create_responsibility` (service layer) but frontend doesn't validate before sending.

**Implementation needed:**
- Pre-flight check: `GET /schools/{schoolId}/employees/{empId}/responsibilities` before assignment
- Show inline validation error in `BulkAssignModal` or `AssignEmployee` modal
- Highlight already-assigned employees with a warning icon

### 5.5 🟡 MEDIUM — Space Responsibility Tab Integration

**Current state:** `SpaceResponsibilityTab.jsx` is imported and used in `SpaceDetailModal.jsx` (as `SpacePage.jsx` references), but:

**Check needed:**
- Verify `SpaceDetailModal` or `SpacePage` properly fetches `getSpaceResponsibilities` and passes data to the tab
- Ensure the tab shows up in the space detail view consistently

## 6. Cross-Cutting Issues

### 6.1 🟠 HIGH — No Shared Contract/Type Definitions

**Problem:** Four separate applications (Rust backend, React frontend, Flutter employee, Flutter chatra) each define their own interface to the Responsibility API. There is no shared OpenAPI/Swagger spec, no shared TypeScript/Dart types, and no contract tests.

**Fix:** Create an OpenAPI 3.0 spec for all Responsibility endpoints, then generate client code for both React (RTK Query) and Flutter (Dart models).

### 6.2 🟡 MEDIUM — No End-to-End Tests

**Problem:** No integration test covers the full flow: Create Responsibility → Assign to Employee → Generate Salary → Sync Student Fees → View in Mobile App.
