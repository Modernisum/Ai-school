# Timetable & Auto-Scheduling Implementation Plan (Revised)

## Goal
Implement a comprehensive Timetable management system in the Vidhyam Admin portal, integrating existing "Space" and "Responsibility" logic with AI-driven auto-scheduling and a visual drag-and-drop interface.

## Strategy: Reuse existing endpoints maximally, only create truly new backend APIs, add comprehensive tests

---

## Backend: New Endpoints Required (Minimal)

### 1A. School Hours & Config
**`GET/PUT /school/:schoolId/timetable/config`**
- Reuses existing `school_profile` or `settings` table — no new table if `data` JSONB field exists

### 1B. Quota Management
**`GET/POST/PUT /school/:schoolId/timetable/quotas`**
- New `timetable_quotas` table: `(school_id, space_id/class, subject, required_periods)`

### 1C. AI Timetable Generation
**`POST /school/:schoolId/timetable/ai/generate`**
- Follow existing `ai_generate_tasks` pattern from `Backend/src/routes/ai.rs`
- Returns multiple timetable options as JSON

### 1D. Manual Timetable CRUD
**`GET/POST/PUT/DELETE /school/:schoolId/timetable`**
- New `timetable_entries` table: `(school_id, day, slot_index, space_id, employee_id, responsibility_id, subject)`
- UNIQUE constraint on `(school_id, day, slot_index, space_id)` and `(school_id, day, slot_index, employee_id)`

### 1E. Conflict Check
**`POST /school/:schoolId/timetable/validate`**
- Server-side validation: checks teacher double-booking, space double-booking

### 1. `TimetablePage.jsx` — Main Container
- Grid layout: Config Section (top) → Quota Section → AI Panel → Grid → Filter Bar
- State management: all timetable data loaded via RTK Query
- Loading/Empty/Error states for each section

### 2. `ConfigForm.jsx` — School Hours & Breaks
- Time pickers for start/end
- Period duration input (minutes)
- Break list with add/remove (lunch, assembly, recess)
- Data reuses `timetable_config` API

### 3. `QuotaMatrix.jsx` — Subject-Period Quotas
- Table: rows = spaces/classes, columns = subjects/responsibilities
- Input cells for required periods per week
- Pre-populates from existing responsibility data

### 4. `AiGenerationPanel.jsx` — AI Trigger & Selection
- "Generate Smart Timetable" button with loading spinner
- Tabs for each generated option
- Side-by-side comparison or preview cards
- "Select & Apply" button per option

### 5. `TimetableGrid.jsx` — Visual Grid (Core)
- Rows = Time Slots, Columns = Days (Mon-Sat)
- Cell shows: Subject + Teacher name
- Drag-and-drop: move cell content between slots
- Conflict highlighting: RED border + Tooltip on clash
- Read-only for break/lunch slots
- Height management: scrollable for many periods

### 6. `ConflictAlert.jsx` — Live Conflict Display
- Small floating banner/popup showing:
  - "Teacher X double-booked at Slot Y"
  - "Room Z double-booked at Slot W"
- Dismissible, auto-updates on drag

### 7. `FilterBar.jsx` — Smart Filters
- Dropdown: "Class/Space", "Teacher", "Room"
- Filters the grid view dynamically
- "Reset" button clears filter

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Conflict enforced at DB level | UNIQUE constraints prevent double-booking at the most fundamental level |
| AI generation as async POST | Follows existing `ai_generate_tasks` pattern; result polling via GET |
| Timetable config in own table | Clean separation from school_profile; JSONB `break_slots` for flexibility |
| Drag-and-drop via HTML5 DnD | No extra library needed for initial implementation; can upgrade to react-beautiful-dnd later |
| Grid rendering via CSS Grid | Native browser support, responsive, no heavy grid library dependency |

---

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| AI generation takes >30s | Return generation ID immediately; frontend polls for result |
| Large schools with 1000+ entries | Paginate timetable by week; backend compresses to per-week views |
| Drag-and-drop UX complexity | Start with simple HTML5 DnD; add react-beautiful-dnd in Phase 2 |
| Conflict data stale after drag | Re-validate on every drag-end action; show live update |
| School hours change mid-semester | Config supports versioning via updated_at; old timetables reference old config
