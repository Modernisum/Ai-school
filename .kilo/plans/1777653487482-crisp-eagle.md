# Chatra App Performance Optimization Plan

## Problem Summary
The Chatra app runs slow on the Android emulator (and likely low-end devices). Key symptoms from logs:
- **282 skipped frames** during initial load
- **211 skipped frames** during navigation
- Janky UI, laggy interactions

## Root Cause Analysis

### CRITICAL — Excessive GPU Work
1. **`BackdropFilter` abuse** — Used in 6+ places (`GlassCard`, `NavbarScreen`, `HomeScreen` appBar, `SpotlightSearchWidget`, `BusTrackingScreen`). Each `BackdropFilter` forces a full-screen GPU read-back per frame. On low-end GPUs this alone causes 50%+ frame drops.
2. **`AnimatedGradientBg` runs continuously** — A 4-second repeating animation that redraws a gradient on every frame, even when the screen is idle. Used in `ClassroomScreen`, `AnnouncementScreen`, `LiveClassroomScreen`, `NavbarScreen`.
3. **Multiple overlapping gradients** — `HomeScreen` paints a static gradient background AND `NavbarScreen` wraps children in `AnimatedGradientBg`, causing double gradient paint.

### HIGH — Widget Rebuild Overkill
4. **`IndexedStack` keeps all 4 tabs alive** — `HomeScreen`, `ClassroomScreen`, `AnnouncementScreen`, `AccountScreen` are all built and laid out simultaneously. HomeScreen alone has 8+ widgets, each with animations.
5. **`flutter_animate` used on every widget** — `QuickActionGrid`, `DashboardStatsWidget`, `AttendanceRadarWidget`, `FeesPreviewWidget`, `HomeGreetingWidget`, nav items, etc. Each `.animate()` creates its own animation controller. On the home screen alone there are ~10+ concurrent animations.
6. **No `const` constructors on frequently-rebuilt widgets** — Many `GoogleFonts.outfit()` calls create new `TextStyle` objects on every build.

### MEDIUM — Startup & Memory
7. **Sequential async work in `main()`** — Firebase init + secure storage read on startup, plus `DashboardBloc` fires 4 parallel API calls immediately.
8. **`GoogleFonts` runtime font loading** — Downloads or parses font data at runtime instead of bundling.
9. **`FlutterSecureStorage` algorithm migration** on first run adds ~1-2s startup delay.

### LOW — Architecture
10. **Bus tracking rebuilds entire `GoogleMap`** on every position update via `AnimatedBuilder` — should update only the marker.
11. **No image caching strategy** for profile pictures.
12. **`quick_action_grid.dart` routes are wrong** — `/tracking`, `/attendance`, `/vault` don't match the actual deferred routes (`/tracking/:schoolId/:vehicleId`, `/attendance/:schoolId/:studentId`, `/vault/:schoolId/:studentId`), causing failed navigations and wasted renders.

## Optimization Plan (Ordered by Impact)

### Phase 1: GPU Load Reduction (Biggest Win — ~60% frame drop reduction)

#### 1.1 Replace `BackdropFilter` in `GlassCard` with static translucent backgrounds
- **File**: `lib/widgets/glass_card.dart`
- **Change**: Remove `BackdropFilter` + `ClipRRect`. Replace with `Container` using `Color(0x1AFFFFFF)` background + subtle border. Keep the visual aesthetic without GPU read-backs.
- **Impact**: Eliminates 6+ full-screen GPU read-backs per frame.

#### 1.2 Replace `BackdropFilter` in `NavbarScreen` bottom nav
- **File**: `lib/navbar_screen.dart`
- **Change**: Replace `ClipRRect > BackdropFilter > Container` with a simple `Container(color: Color(0xCC1E1440))` (dark semi-transparent background). No blur needed for a small bottom bar.
- **Impact**: Removes 1 more GPU read-back on every frame.

#### 1.3 Replace `BackdropFilter` in `HomeScreen` glass app bar
- **File**: `lib/features/home/screens/home_screen.dart`
- **Change**: Replace `ClipRRect > BackdropFilter` with a semi-transparent `Container` with no blur.

#### 1.4 Replace `BackdropFilter` in `SpotlightSearchWidget` overlay
- **File**: `lib/features/home/widgets/spotlight_search_widget.dart`
- **Change**: Replace `BackdropFilter(filter: ImageFilter.blur(...))` with `Container(color: Colors.black.withOpacity(0.85))`.

#### 1.5 Make `AnimatedGradientBg` static by default, animate only on first appearance
- **File**: `lib/widgets/animated_gradient_bg.dart`
- **Change**: Run the animation once (4s) then stop. Add `animate: false` parameter for screens where no animation is needed. The gradient should be a static `LinearGradient` after initial fade-in.
- **Impact**: Eliminates continuous per-frame redraw of background gradient.

#### 1.6 Remove duplicate gradient in `HomeScreen`
- **File**: `lib/features/home/screens/home_screen.dart`
- **Change**: `HomeScreen` already has its own `Container(decoration: BoxDecoration(gradient: ...))`. Remove `AnimatedGradientBg` usage from NavbarScreen for the Home tab, or let HomeScreen use a plain background since NavbarScreen already wraps with `AnimatedGradientBg`.

### Phase 2: Reduce Rebuilds & Animation Overhead (~30% frame drop reduction)

#### 2.1 Lazy-load tabs instead of `IndexedStack`
- **File**: `lib/navbar_screen.dart`
- **Change**: Replace `IndexedStack` with a `PageView`-like approach or simply swap the active widget. Use `AutomaticKeepAliveClientMixin` to preserve state of visited tabs. Only build the visible tab.
- **Impact**: Eliminates building 3 hidden screens simultaneously.

#### 2.2 Reduce `flutter_animate` usage to essentials only
- **Files**: All widget files
- **Change**: Remove `.animate()` from:
  - `QuickActionGrid` items (5 items × animation = 5 controllers)
  - `DashboardStatsWidget` stat cards (4 cards)
  - `AttendanceRadarWidget` (small card, no need)
  - `FeesPreviewWidget` (small card, no need)
  - `HomeGreetingWidget` (replace with a simple `FadeIn` once)
  - Nav bar item scale animations (runs on every tap)
  - `NavbarScreen` bottom nav slide-in (runs once, fine to keep)
- Keep animations only for: page transitions, dialog appearances, critical feedback.
- **Impact**: Reduces concurrent animation controllers from ~15+ to ~3-4.

#### 2.3 Cache `GoogleFonts.outfit()` text styles
- **Files**: All widget files
- **Change**: Create a `TextStyles` class in `app_theme.dart` with pre-built `TextStyle` objects. Replace all `GoogleFonts.outfit(...)` calls with static references.
- **Impact**: Eliminates object allocation on every `build()`.

#### 2.4 Bundle `Outfit` font instead of using `google_fonts` runtime
- **File**: `pubspec.yaml`, `lib/theme/app_theme.dart`
- **Change**: Download Outfit font TTF, add to `pubspec.yaml` fonts section. Replace `GoogleFonts.outfitTextTheme()` with `ThemeData(textTheme: Typography().white.copyWith(...))` using the bundled font family.
- **Impact**: Removes runtime font download/parse overhead. `google_fonts` package can potentially be removed entirely.

### Phase 3: Startup Optimization (~40% faster cold start)

#### 3.1 Defer Firebase initialization
- **File**: `lib/main.dart`
- **Change**: Run `Firebase.initializeApp()` in a splash screen or use `FutureBuilder` with a lightweight splash, not blocking `runApp()`. Show the app shell immediately, init Firebase in background.
- **Impact**: App shell renders 200-500ms faster.

#### 3.2 Defer dashboard API calls
- **File**: `lib/features/home/screens/home_screen.dart`
- **Change**: Don't fire dashboard API calls in `initState`. Use a skeleton loader for the first 300ms, then fetch. This gives the UI time to settle before network work begins.

#### 3.3 Add `flutter_secure_storage` migration handling gracefully
- **File**: `lib/main.dart`
- **Change**: The algorithm migration runs on first launch. Consider pre-warming or showing a branded loading screen during this migration.

### Phase 4: Specific Screen Optimizations

#### 4.1 Fix `BusTrackingScreen` marker updates
- **File**: `lib/features/transport/screens/bus_tracking_screen.dart`
- **Change**: Remove `AnimatedBuilder` wrapping `GoogleMap`. Instead, update only the `Marker` position via `setState` on the markers set. GoogleMap handles marker position changes internally.
- **Impact**: Eliminates full map widget rebuild on every GPS update.

#### 4.2 Fix `QuickActionGrid` route paths
- **File**: `lib/features/home/widgets/quick_action_grid.dart`
- **Change**: Update routes to match actual deferred paths, or make routes parameterized from the router.
- **Impact**: Prevents failed navigations and wasted renders.

#### 4.3 Use `RepaintBoundary` strategically on `HomeScreen`
- **File**: `lib/features/home/screens/home_screen.dart`
- **Change**: Already has some `RepaintBoundary` usage. Add one around the entire scroll content area and the search overlay separately.

### Phase 5: Build & Release Optimizations

#### 5.1 Enable R8/ProGuard for release builds
- **File**: `android/app/build.gradle.kts`
- **Change**: Add `isMinifyEnabled = true` and `isShrinkResources = true` in release build type. Create ProGuard rules.
- **Impact**: 30-50% smaller APK, faster startup.

#### 5.2 Use `--split-per-abi` for APK builds
- **Impact**: Reduces APK size by ~40% by building architecture-specific APKs.
