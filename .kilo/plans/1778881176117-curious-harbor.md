## Phase 1: Backend — 3 New Route Handlers (Minimal)

### 1A. `GET /api/v1/:schoolId/spaces/:spaceName/materials`

**Why new:** The `space_materials` table exists but has no GET endpoint. The `get_material()` returns `occupiedSpaces` from the material side, but there's no dedicated endpoint from the space side.

**Existing table:** `space_materials` (`school_id, space_id, space_name, material_id, material_name, quantity, unit, unit_price`)

**Route registration path:** `Backend/src/domain/resources.rs` + `Backend/src/routes/spaces.rs`

**Repository query (simple SELECT):**
```sql
SELECT m.*, COALESCE(req.required_count, 0) as required_count
FROM space_materials m
LEFT JOIN space_material_requirements req 
  ON req.school_id = m.school_id 
  AND req.space_id = m.space_id 
  AND req.material_name = m.material_name
WHERE m.school_id = $1 AND m.space_name = $2
```

**Response:**
```json
{
  "success": true,
  "materials": [
    { "materialName": "Ceiling Fan", "materialId": "MAT-xxx", "quantity": 3, "requiredCount": 4, "unit": "pcs", "unitPrice": 2500, "status": "deficit" }
  ]
}
```

**New trait method:** `get_space_materials(school_id, space_name) -> AppResult<Vec<Value>>`
**Add to:** `Backend/src/services/traits/resource.rs` ResourceService trait
**Add to:** `Backend/src/repository/resource_repo.rs` PostgresResourceRepository impl

### 1B. `POST /api/v1/:schoolId/spaces/:spaceName/clone`

**Why new:** No existing endpoint can duplicate a space with its material requirements and responsibility requirements.

**Request:**
```json
{ "newSpaceName": "Class 1-C" }
```

**Response:**
```json
{ "success": true, "spaceId": "class-1-c-xxxx", "spaceName": "Class 1-C", "clonedFrom": "Class 1-B" }
```

**Repository logic (transactional):**
1. SELECT source space → get space_category, space_number, data
2. Generate new space_id from newSpaceName
3. INSERT new space row
4. COPY `space_material_requirements` rows (new space_id, same material_name + required_count)
5. COPY `space_requirements` rows (new space_id, same responsibility_id + required_count)
6. DO NOT copy: space_materials (actual quantities), space_employees (hr assignments)

**New trait method:** `clone_space(school_id, source_space_name, new_space_name) -> AppResult<Value>`
**Add to:** resource service trait + resource_repo

---

### 1C. `POST /api/v1/:schoolId/spaces/:fromSpace/materials/:materialName/transfer`

**Why new:** `assign_space_materials` adds materials from inventory; `remove_space_material` returns to inventory. Neither moves between two spaces.

**Request:**
```json
{ "toSpace": "Class 1-C", "quantity": 2 }
```

**Response:**
```json
{ "success": true, "remainingInSource": 1, "newQuantityInTarget": 2 }
```

**Repository logic (transactional):**
1. Validate: source space has the material with sufficient quantity
2. UPDATE `space_materials` SET `quantity = quantity - $qty` WHERE space_name = fromSpace
3. INSERT/UPDATE `space_materials` SET `quantity = quantity + $qty` WHERE space_name = toSpace
4. INSERT into `material_history` with `action_type = 'TRANSFER'`, `space_name = fromSpace` and notes mentioning toSpace
5. If source quantity reaches 0 after transfer: DELETE the row

**New trait method:** `transfer_space_material(school_id, from_space, to_space, material_name, quantity) -> AppResult<Value>`
**Add to:** resource service trait + resource_repo

### 3A. `SpaceDashboard.jsx` — Top Stats Section

**Reuses existing endpoints (NO new backend needed):**
- `GET /spaces` → count spaces, group by category for KPI
- `GET /spaces/categories` → list of categories
- `GET /responsibility/metrics/space-distribution` → employee counts per space
- Financial overview: computed FRONTEND-SIDE by aggregating material values from `GET /spaces/:name/materials` across spaces (or we can do it via a single parallel batch)

**States:**
- Loading: `SkeletonLoader` card variant (3 skeleton cards)
- Empty: No spaces created yet → "Create your first space" prompt
- Error: Display error message with retry
- Data Ready: KPI cards + alert banner + category financial table

**KPIs displayed:**
- Total Spaces (count)
- Categories (count distinct)
- Total Assigned Employees
- Alerts (count of spaces with deficits)

### 3B. `SpaceDataGrid.jsx` — Filterable Table

**Reuses `DataGrid` component (already exists at `components/ui/DataGrid.jsx`)**

**Features:**
- Search by space name (client-side filter)
- Category filter dropdown (from `GET /spaces/categories`)
- Status filter: All / Full / Deficient (computed from materials data)
- Employee count filter: All / 0 / 1-2 / 3-5 / 5+
- Quick actions: Edit → opens edit form, Delete → confirm dialog, View → opens SpaceDetailModal
- Pagination: 20 per page

**Status computation (client-side from materials data):**
- Call `GET /spaces` to get all spaces
- For each space with materials data, check if any material has `available < required`
- Status: "Full" if all materials available >= required, "Deficient" otherwise

### 3C. `SpaceDetailModal.jsx` — 3-Tab Container

**Data fetched in parallel from EXISTING endpoints:**
1. `GET /spaces/detail/:spaceName` — space metadata (exists)
2. `GET /spaces/:spaceName/materials` — materials with required vs available (NEW, Phase 1)
3. `GET /responsibility/spaces/:spaceId/responsibilities` — space responsibilities (exists)

**Tab 1: Materials** → `SpaceMaterialTab.jsx`
- Progress bar per material: `(available / required) * 100%`
- Color: green (>=100%), yellow (>=50%), red (<50%)
- "Transfer" button per row → opens `TransferMaterialModal.jsx`
- "Add Material" button → opens existing assign materials form
- Shows `unit_price * quantity = total_value` per material

**Tab 2: Responsibilities** → `SpaceResponsibilityTab.jsx`
- Shows: responsibility name, assigned employee name, cost/month, fee/student
- "Unassigned" badge with ⚠ for missing employees
- "Assign Employee" button → opens assignment modal
- Duplicate prevention: frontend checks if employee already assigned + backend UNIQUE constraint on `space_employees(school_id, space_id, employee_id)`
- Error alert popup on duplicate attempt

**Tab 3: Consumers** → `SpaceConsumersTab.jsx`
- Fetches students whose class+section matches the space name
- REUSES existing student API: `GET /students?class=X&section=Y` (if available) or filters from all students
- Shows: name, class, section, consumed fees
- Total count + total fee revenue footer

### 3D. `SpaceCreateForm.jsx` + `CloneSpaceModal.jsx`

**Form fields:**
- Space Name (required)
- Category (dropdown from `GET /spaces/categories`)
- Space Number (optional, e.g., "1-B")

**Clone integration (same form, toggle switch):**

**Validation:**

### 3E. `TransferMaterialModal.jsx`

## Phase 4: Frontend RTK Query API Layer

**Edit: `frontend/Vidhyam/src/features/infrastructure/api/infrastructureApi.js`**

Add `injectEndpoints` calls for 3 new backend routes:

```js
// In existing infrastructureApi.js — inject new endpoints
getSpaceMaterials: builder.query({
  query: ({ schoolId, spaceName }) => `/spaces/${encodeURIComponent(spaceName)}/materials`,
  providesTags: ['SpaceMaterials']
}),
cloneSpace: builder.mutation({
  query: ({ schoolId, spaceName, body }) => ({
    url: `/spaces/${encodeURIComponent(spaceName)}/clone`,
    method: 'POST',
    body
  }),
  invalidatesTags: ['Spaces', 'SpaceMaterials']
}),
transferMaterial: builder.mutation({
  query: ({ schoolId, fromSpace, materialName, body }) => ({
    url: `/spaces/${encodeURIComponent(fromSpace)}/materials/${encodeURIComponent(materialName)}/transfer`,
    method: 'POST',
    body
  }),
  invalidatesTags: ['Spaces', 'SpaceMaterials', 'Materials']
}),
```

No new file — extend existing `infrastructureApi.js` to avoid fragmenting API definitions.

## Key Design Decisions

| Decision | Rationale |
|----------|-----------|
| Only 3 new backend endpoints | Clone, Transfer, and Materials-for-Space are truly new functionality. Everything else computed frontend-side from existing data |
| No new database tables/schema | All new endpoints read/write existing tables only |
| Financial overview computed frontend-side | Aggregating `GET /spaces` + `GET /spaces/:name/materials` data avoids backend work |
| Requirement status filter computed frontend-side | Compare available vs required from materials data per space |
| Extend existing infrastructureApi.js | Avoid fragmenting API definitions; keep single source of truth |
| Jest (existing react-scripts test) not vitest | Vidhyam already has Jest + RTL configured; avoid adding new test framework |
| Reuse DataGrid, KPIWidget, GlassCard | Existing components already have loading/empty/error states |
| Duplicate prevention: frontend + backend | Frontend shows immediate alert; backend UNIQUE constraint is safety net |

## Risk Mitigation

| Risk | Mitigation |
|------|------------|
| N+1 API calls in detail view | Make 3 parallel requests (Promise.all) — network latency minimized |
| Financial overview performance with many spaces | Paginate, show top 10 categories only |
| Clone fails mid-way | Wrapped in DB transaction with rollback |
| Transfer race condition | DB-level atomic UPDATE with RETURNING verification |
| Frontend test reliance on RTK Query mocks | Mock at API hook level (useGetXxxQuery), NOT at fetch level |
