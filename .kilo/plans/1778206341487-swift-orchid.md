## Phase 1: Project Scaffolding & Backend CMS Foundation

### 1.2 Backend CMS Database Tables
Create migration `202605080000_cms_tables.sql`:

```sql
-- Blog posts table
CREATE TABLE IF NOT EXISTS blog_posts (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    slug VARCHAR(255) UNIQUE NOT NULL,
    title VARCHAR(500) NOT NULL,
    excerpt TEXT,
    content TEXT NOT NULL,
    cover_image_url VARCHAR(1000),
    author_name VARCHAR(255) DEFAULT 'Vidhyam Team',
    category VARCHAR(100),
    tags TEXT[] DEFAULT '{}',
    seo_title VARCHAR(200),
    seo_description VARCHAR(500),
    is_published BOOLEAN DEFAULT false,
    published_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Testimonials table
CREATE TABLE IF NOT EXISTS testimonials (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    client_name VARCHAR(255) NOT NULL,
    client_title VARCHAR(255),
    school_name VARCHAR(500),
    avatar_url VARCHAR(1000),
    rating SMALLINT CHECK (rating BETWEEN 1 AND 5),
    content TEXT NOT NULL,
    is_featured BOOLEAN DEFAULT false,
    display_order INT DEFAULT 0,
    is_published BOOLEAN DEFAULT false,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- School access requests (lead gen)
CREATE TABLE IF NOT EXISTS school_access_requests (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    school_name VARCHAR(500) NOT NULL,
    contact_name VARCHAR(255) NOT NULL,
    email VARCHAR(255) NOT NULL,
    phone VARCHAR(50),
    employee_count INT,
    student_count INT,
    message TEXT,
    status VARCHAR(50) DEFAULT 'pending',
    -- 'pending', 'contacted', 'approved', 'rejected'
    admin_notes TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Indexes
CREATE INDEX idx_blog_posts_slug ON blog_posts(slug);
CREATE INDEX idx_blog_posts_published_at ON blog_posts(published_at DESC);
CREATE INDEX idx_testimonials_featured ON testimonials(is_featured, display_order);
CREATE INDEX idx_school_requests_status ON school_access_requests(status);
```

- Create `src/routes/blog.rs` — public endpoints: `GET /api/cms/blog` (list), `GET /api/cms/blog/:slug` (detail)
- Create `src/routes/blog.rs` — admin endpoints: `POST/PUT/DELETE /api/cms/blog` (CRUD)
- Create `src/routes/testimonials.rs` — public: `GET /api/cms/testimonials`

  - `lib/api/storage.ts` — `uploadImage(file)`, `getFileUrl(fileId)`

- Create `lib/types/` with all TypeScript interfaces

## Phase 5: Lead Generation System

**Duration:** 1 day | **Priority:** HIGH

### 5.1 Request Access Form
- **Component:** `components/forms/RequestAccessForm.tsx`
- **Placement:** Multiple locations:
  - Inline CTA section on landing page
  - Dedicated `/get-started` page
  - Floating modal (triggered by "Request Access" button)
  - Bottom sticky bar (mobile)
- **Form Fields:**
  - School Name (required)
  - Contact Person Name (required)
  - Email (required, validated)
  - Phone Number (required)
  - Number of Employees (select)
  - Approximate Student Count (select)
  - Message/Requirements (textarea, optional)
- **States:** idle → validating → submitting → success → error
- **Validation:** client-side (Zod) + server-side response handling
- **Success State:** Animated checkmark + "Request submitted! Our team will contact you within 24 hours."

### 5.2 API Integration
- **Workflow:**
  1. Form submits to `POST /api/cms/school-request` (stores in DB)
  2. On success, trigger `POST /api/admin/notify/global` to notify SuperAdmin
  3. Display success confirmation to user
- Create `aischool/lib/api/lead-gen.ts`:
  ```typescript
  async function submitSchoolRequest(data: SchoolAccessRequest): Promise<ApiResponse<{id: string}>>
  ```
- Create `aischool/lib/api/notifications.ts`:
  ```typescript
  async function sendSchoolAccessNotification(schoolName: string, contactEmail: string): Promise<void>
  ```
- **Error handling:** Network failures → retry once, validation errors → inline field errors, server errors → generic message

### 5.3 SuperAdmin Integration
- `POST /api/cms/school-request` endpoint stores request in `school_access_requests` table
- SuperAdmin dashboard (`frontend/SuperAdmin`) lists and manages incoming requests
- SuperAdmin can: view details, mark as contacted, approve/reject, add admin notes
- No SuperAdmin details exposed on public website

### 5.4 Deliverables Check
- [ ] Form submits and stores data via API
- [ ] SuperAdmin receives notification
- [ ] All form states render correctly
- [ ] Client-side validation catches invalid inputs
- [ ] Rate limiting prevents abuse (cooldown between submissions)
