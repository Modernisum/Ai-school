# AI-Driven Syllabus Calendar & Smart Timetable — Implementation Plan

## Overview
Build an AI-powered syllabus calendar system with period-level micro-planning, daily
teacher todo/reporting, smart timetable generation with issue-box validation, and
emergency block-merging/substitution — all with Admin supremacy.

---

## Phase 1: Backend Schema & Infrastructure

### 1.1 New Tables (in `schema_setup.rs`)

```sql
-- Syllabus Calendar: one row per class-subject-chapter with date planning
CREATE TABLE syllabus_calendar (
    id SERIAL PRIMARY KEY,
    school_id VARCHAR(255) NOT NULL,
    class_id VARCHAR(255) NOT NULL,
    subject_id VARCHAR(255) NOT NULL,
    chapter_id INTEGER NOT NULL REFERENCES chapters(id) ON DELETE CASCADE,
    planned_start_date DATE NOT NULL,
    planned_end_date DATE NOT NULL,
    actual_start_date DATE,
    actual_end_date DATE,
    period_count INTEGER DEFAULT 0,     -- how many 45-min blocks allocated
    status VARCHAR(20) DEFAULT 'pending', -- pending | in_progress | completed | delayed
    quarter VARCHAR(5),                   -- Q1/Q2/Q3/Q4
    UNIQUE(school_id, class_id, subject_id, chapter_id, quarter)
);

-- Period-Level Plan: one row per teaching block
CREATE TABLE period_plans (
    id SERIAL PRIMARY KEY,
    school_id VARCHAR(255) NOT NULL,
    class_id VARCHAR(255) NOT NULL,
    subject_id VARCHAR(255) NOT NULL,
    config_id TEXT NOT NULL REFERENCES timetable_configs(config_id),
    day_of_week INTEGER NOT NULL,
    period_number INTEGER NOT NULL,
    date DATE NOT NULL,
    chapter_id INTEGER REFERENCES chapters(id),
    topic_name TEXT,                      -- specific topic(s) to cover
    teacher_id TEXT NOT NULL,
    status VARCHAR(20) DEFAULT 'pending', -- pending | completed | missed | rescheduled
    teacher_note TEXT,
    completed_at TIMESTAMP WITH TIME ZONE,
    UNIQUE(school_id, config_id, day_of_week, period_number, date)
);

-- Block Merge / Substitute Requests
CREATE TABLE schedule_change_requests (
    id SERIAL PRIMARY KEY,
    school_id VARCHAR(255) NOT NULL,
    type VARCHAR(30) NOT NULL,            -- block_merge | skip | substitute
    requested_by TEXT NOT NULL,           -- teacher_id who requested
    approved_by TEXT,                     -- admin who approved/rejected
    status VARCHAR(20) DEFAULT 'pending', -- pending | approved | rejected
    source_class_id TEXT,
    source_subject_id TEXT,
    target_class_id TEXT,
    target_subject_id TEXT,
    reason TEXT,
    admin_note TEXT,
    date_from DATE,
    date_to DATE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP WITH TIME ZONE
);

-- Daily Teacher Reports
CREATE TABLE daily_teacher_reports (
    id SERIAL PRIMARY KEY,
    school_id VARCHAR(255) NOT NULL,
    teacher_id TEXT NOT NULL,
    report_date DATE NOT NULL,
    status VARCHAR(20) DEFAULT 'pending', -- pending | submitted | reviewed
    summary TEXT,
    pending_topics JSONB DEFAULT '[]',
    completed_periods INTEGER DEFAULT 0,
    total_periods INTEGER DEFAULT 0,
    submitted_at TIMESTAMP WITH TIME ZONE,
    UNIQUE(school_id, teacher_id, report_date)
);
```

## Phase 2: Backend Logic

### 2.1 AI Syllabus Plotter (`src/logic/ai/syllabus_planner.rs`)

**Function: `annual_syllabus_plot(school_id, class_id, subject_id, academic_year)`**
1. Fetch all chapters for the subject with weightage
2. Calculate available teaching days: April 1 – March 31, exclude Sundays + holidays
3. Divide into 4 quarters (Q1: Apr-Jun, Q2: Jul-Sep, Q3: Oct-Dec, Q4: Jan-Mar)
4. Distribute chapters across quarters using weightage (reuse `get_auto_syllabus` algorithm)
5. For each chapter, assign `planned_start_date` / `planned_end_date` within its quarter
6. Allocate period_count = (chapter_weight / total_weight) × periods_per_quarter
7. Insert rows into `syllabus_calendar`
8. **Quarterly boundary enforcement**: If any chapter in Q1 would overflow into Q2, raise an alert (never auto-move)

**Function: `micro_plan_period_level(school_id, class_id, subject_id, date_range)`**
1. Load timetable slots for the class (from timetable_slots)
2. For each day+period that has this subject+teacher, assign 1-2 specific topics from the scheduled chapter
3. Insert into `period_plans` — one row per period block
4. Return structured daily todo data

### 2.2 AI Auto-Restructure (`src/logic/ai/prediction.rs` — extend)

**Function: `restructure_syllabus_on_delay(school_id, teacher_id, date)`**
1. Find pending/incomplete period_plans before `date` for the teacher
2. Identify which chapters/topics are behind
3. Look ahead at remaining period_plans in the same quarter
4. Redistribute uncompleted topics into future periods within the SAME quarter
5. If quarter would be exceeded, generate a **schedule_change_request** for admin
6. Update `syllabus_calendar` dates and `period_plans` accordingly

### 2.3 Smart Timetable — Multi-Option & Issue Box

**File: `src/logic/timetable_engine.rs` — extend**

**New function: `generate_multi_option(school_id, class_id, params, count=4)`**
1. Run the existing greedy CSP 4 times with different random seeds for input ordering (subject requirements shuffled each run)
2. Score each result: fewer conflicts (weighted high), higher utilization, teacher preference satisfaction
3. Return top 3-4 options with score metadata per option (conflict count, utilization %, free period ratio)
4. Admin selects one → call existing `save_timetable()` + `approve_timetable()`

**New function: `validate_issue_box(school_id, config_id)`**
1. Scan all slots in the timetable for the class
2. Flag: any period with `is_free_period = TRUE` → HIGH priority alert
3. Flag: any subject without assigned teacher → HIGH priority alert
4. Return structured issue box report with counts + details

### 2.4 Emergency & Substitute (`src/logic/timetable_engine.rs` — extend)

Already has `find_available_substitutes()`. Add:
- **`find_best_substitute(school_id, class_id, subject_id, day, period)`** — ranks substitutes by subject match + availability + current load
- **`suggest_block_merge(school_id, teacher_id, class_id, subject_id, date)`** — finds another teacher who is ahead of syllabus for the same class+subject, suggests merging their period slot

### 2.5 Daily Report & Follow-up

**Function: `check_daily_report(school_id, date)`**
1. Query all teachers who have period_plans for `date`
2. Check if they submitted `daily_teacher_reports` for that date
3. For missing reports → create notification + block the app next login
4. Auto-generate next day's todo from period_plans
