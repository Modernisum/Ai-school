# Platform Admin Guides

Yeh folder `rust/src/domain/admin/mod.rs` aur nested CMS admin routes ke liye fresher-friendly backend documentation rakhta hai.

## Files

- `admin_guide.md`: High-level domain overview, architecture, feature purpose, aur developer laws.
- `endpoint_reference.md`: `rust/src/domain/admin/mod.rs` ke har admin endpoint ka method, auth requirement, request body/query/path params, expected success response, aur common error response.
- `test_cases.md`: Admin API ke liye manual/API test cases, curl examples, aur expected assertions.
- `implementation_plan.md`: Naye admin endpoint add/modify karte waqt follow karne wala implementation plan.

## Base routing

Admin routes are mounted as `/api/admin` because `domain::create_router` nests all domain routes under `/api` in `rust/src/domain/mod.rs`.

Example:

```bash
GET /api/admin/profile
POST /api/admin/login
```

## Admin auth pattern

Except `POST /api/admin/login`, all admin endpoints require:

```http
Authorization: Bearer <accessToken>
```

The admin token is generated by `services/admin/auth.rs` as:

```text
base64(username:timestamp:SUPER_ADMIN_SECRET)
```

`require_admin!` verifies the token, checks `SUPER_ADMIN_SECRET`, and rejects expired/tampered tokens.

## Response envelope

Most admin endpoints use these macros:

```rust
ok_json!(data)
err_json!(e)
not_found_json!(msg)
```

Expected success envelope:

```json
{
  "success": true,
  "data": {}
}
```

Expected error envelope:

```json
{
  "success": false,
  "message": "Human readable error"
}
```

Some endpoints intentionally return non-envelope responses, especially file exports. Those endpoints are marked separately in `endpoint_reference.md`.
