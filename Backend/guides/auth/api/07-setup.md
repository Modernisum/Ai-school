# Setup API Contract

Covers new school creation.

Routes:

- `POST /api/auth/setup/school`

Source:

- Route registration: `rust/src/domain/auth/mod.rs`
- Setup school handler: `rust/src/domain/auth/setup.rs`
- Setup service: `rust/src/services/auth/setup_service.rs`
- RLS public list: `rust/src/middleware/rls.rs`

## Current-code auth note

`POST /api/auth/setup/school` is not listed as public in current RLS middleware. It requires a valid bearer token before the handler runs.

## `POST /api/auth/setup/school`

### Purpose

Creates a new school tenant, initializes default academic structure, and attempts automatic login.

### Auth

Bearer token required by current RLS middleware. If public onboarding is intended later, this must be explicitly added to RLS public paths and hardened.

### Request body

```json
{
  "schoolName": "Green Valley Academy",
  "schoolAddress": "128 Main Street, City",
  "password": "adminPassword123",
  "adminEmail": "admin@greenvalley.com",
  "adminPhone": "+919876543210",
  "classLevelStart": 1,
  "classLevel": 10
}
```

### Expected success response when auto-login succeeds

```json
{
  "success": true,
  "schoolId": "123456",
  "schoolCode": "SCH0025",
  "accessToken": "jwt_token",
  "message": "School setup completed and signed in automatically"
}
```

### Current-code fallback when auto-login fails

Current handler returns raw setup service output if automatic login fails. This is a current-code gap because setup service output can include credential-like fields. Production docs should not treat this fallback as acceptable.

Safe expected response after hardening:

```json
{
  "success": true,
  "schoolId": "123456",
  "schoolCode": "SCH0025",
  "message": "School setup completed, but automatic login failed. Use the setup result to continue onboarding."
}
```

### Expected error response

```json
{
  "success": false,
  "message": "Missing schoolName"
}
```

### Important rules

- Required fields: `schoolName`, `schoolAddress`, `password`.
- `adminEmail` and `adminPhone` are optional.
- If `adminEmail` is missing, default is `admin@<schoolId>`.
- If `adminPhone` is missing, default is `+911234567890`.
- `classLevelStart` and `classLevel` default to `0` when missing.
- A 6-digit numeric `schoolId` is generated.
- A school code is generated by the auth repository.
- A tenant schema is created.
- Default spaces, materials, classes, responsibilities, holidays, and fee templates are created.
- A school admin employee is created with id `admin-<schoolId>`.
- Public setup responses must never expose `password`, `adminPassword`, security answers, or password hashes.

### Test cases

#### TC_AUTH_SETUP_003 Setup school happy path

- Type: positive/integration-only
- Preconditions: Valid bearer token exists. This test provisions a full school tenant and should run serially on disposable test data.
- Request:
  - Method: `POST`
  - Route: `/api/auth/setup/school`
  - Headers: `Authorization: Bearer <school-admin-or-setup-token>`
  - Body:
    ```json
    {
      "schoolName": "Green Valley Academy",
      "schoolAddress": "128 Main Street",
      "password": "adminPassword123",
      "adminEmail": "admin@greenvalley.com",
      "classLevelStart": 1,
      "classLevel": 10
    }
    ```
- Expected HTTP status: `200`
- Expected response: `success == true`, `schoolId` and `schoolCode` are present, `accessToken` is present when auto-login succeeds.
- Database/state assertion: School row, tenant schema, admin user, default classes, responsibilities, holidays, and fees are created.
