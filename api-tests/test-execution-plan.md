# API Test Suite - Execution Plan

This document provides a comprehensive plan for executing the API test suite using Bruno REST client.

## Prerequisites

### 1. Software Requirements

## Test Execution Methods

### Method 1: Manual Testing with Bruno GUI
1. Open Bruno application
2. Import the `api-tests` folder as a collection
3. Set active environment to use `environment.bru`
4. Navigate through categories and run tests individually
5. Verify responses against expected patterns in `.md` files

### Method 2: Automated Testing with Bruno CLI
```bash
# Install Bruno CLI
npm install -g @usebruno/cli

# Run all tests
bruno run api-tests

# Run specific category
bruno run api-tests/categories/01-health.bru

# Run with environment
bruno run api-tests --env api-tests/environment.bru

# Generate test report
bruno run api-tests --report html
```

### Method 3: Script-based Execution
Use the provided validation and execution scripts:
```bash
# Validate all .bru files
node api-tests/validate-bru-files.js

# Run sequential test execution (to be implemented)
node api-tests/run-tests.js
```

## Expected Response Validation

### Success Criteria
1. **HTTP Status Codes**: Verify correct status codes (200, 201, 204 for success)
2. **Response Structure**: Match expected JSON schema
3. **Data Integrity**: Verify returned data matches request data
4. **Error Handling**: Proper error responses for invalid requests

### Validation Rules
- Health endpoints: Should return 200 OK
- Authentication endpoints: Should return tokens or proper errors
- CRUD operations: Should return appropriate status codes (201 Created, 200 OK, 204 No Content)
- List endpoints: Should support pagination and filtering
- Bulk operations: Should handle partial failures gracefully

## Error Handling Tests

### Test Scenarios to Cover
1. **Invalid Authentication**
   - Missing headers
   - Invalid tokens
   - Expired tokens

2. **Invalid Input Data**
   - Missing required fields
   - Invalid data types
   - Out-of-range values

3. **Authorization Failures**
   - Insufficient permissions
   - School access restrictions

4. **Resource Not Found**
   - Invalid IDs
   - Deleted resources

5. **Conflict Scenarios**
   - Duplicate entries
   - Concurrent modifications

## CI/CD Integration

### GitHub Actions Example
```yaml
name: API Tests
on: [push, pull_request]
jobs:
  api-tests:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node.js
        uses: actions/setup-node@v3
      - name: Install Bruno CLI
        run: npm install -g @usebruno/cli
      - name: Start Backend
        run: docker-compose up -d
      - name: Run API Tests
        run: bruno run api-tests --env api-tests/environment.bru --report junit
      - name: Upload Test Results
        uses: actions/upload-artifact@v3
        with:
          name: test-results
          path: reports/
```

### Jenkins Pipeline Example
```groovy
pipeline {
    agent any
    stages {
        stage('Test') {
            steps {
                sh 'npm install -g @usebruno/cli'
                sh 'bruno run api-tests --env api-tests/environment.bru'
            }
        }
    }
}
```
